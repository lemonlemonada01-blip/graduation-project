# المنصة الذكية والمؤمنة مركزياً لإدارة المشاريع والأبحاث الأكاديمية (Secure-FEPRH)
## وثيقة مقترح المشروع والبنية المعمارية الموسعة

---

## 1. المقدمة والرؤية الهندسية
تمثل **Secure-FEPRH** منصة مركزية آمنة مقترحة لإدارة المشاريع الأكاديمية والأبحاث في كلية الهندسة والتكنولوجيا (قسم هندسة الحاسبات والتحكم).

تم تصميم النظام ليكون منصة برمجية متكاملة (Software-Only) على مستوى المؤسسات تدمج بين نظام إدارة الهوية والوصول (IAM) ومستودع رقمي محمي. الهدف هو تنظيم وتوثيق وإدارة مشاريع التخرج باستخدام أحدث تقنيات الأمن السيبراني والذكاء الاصطناعي (الرؤية الحاسوبية ومعالجة اللغات الطبيعية)، مع الحفاظ على جدوى مالية بمنعدم التكلفة (Zero-Budget) من خلال استغلال البنية التحتية والمعدات الحالية.

---

## 2. بيان المشكلة والمبررات
* **غياب الأرشفة والحماية الرقمية:** غالباً ما تتعرض الموارد الهندسية الحيوية (مثل نصوص Python ومحاكاة PIC والدوائر) للضياع أو التسريب أو السرقة بسبب عدم وجود مستودع رقمي محمي.
* **تكرار الأفكار وغياب الأصالة:** تواجه الكلية صعوبة في الفحص الفوري للأفكار المقترحة للتأكد من عدم إعادة تدويرها أو تكرارها من السنوات السابقة.
* **محدودية الميزانية:** شراء معدات مخصصة (مستشعرات، بوابات ذكية، متحكمات) يعتبر غير مجدٍ مالياً. الحل البرمجي بالكامل يستغل البنية التحتية الحالية (أجهزة الحاسوب والكاميرات المدمجة) بفعالية.

---

## 3. الأنظمة الفرعية الأساسية (الأصلية)
1. **نظام إدارة الهوية والأمن السيبراني (IAM & Cyber Security Subsystem):**
   * **المصادقة متعددة العوامل باستخدام القياسات الحيوية للوجه (Biometric Face MFA):** يستخدم فحص الحيوية اللحظية (Liveness Detection) لمنع الاحتيال (مثل استخدام صور مطبوعة أو شاشات هواتف) من خلال التأكد من أن المستخدم أمام الكاميرا كائن حي.
   * **التحكم في الوصول المبني على الأدوار (RBAC):** مصفوفة صلاحيات صارمة تضمن الفصل السليم للمهام بين الطلاب، المشرفين، ورئيس القسم.
2. **محرك الفحص الذكي للتشابه (NLP):**
   * محرك بحث ذكي يحلل الملخصات والكلمات المفتاحية المقدمة.
   * يقارن المشاريع بجميع المشاريع المؤرشفة في قاعدة البيانات لإنشاء تقرير تشابه، مما يساعد في اتخاذ قرار القبول أو الرفض.
3. **مستودع الأكواد الهندسية المحمي (Secure Engineering Code Repository):**
   * أرشيف رقمي مشفر مدمج مع نظام IAM.
   * يتيح للطلاب رفع الأكواد والمحاكاة بأمان، مع قصر الوصول على المشرفين المصرح لهم ورئيس القسم فقط.
4. **نظام الحضور الذكي:**
   * يستخدم الرؤية الحاسوبية لتوثيق حضور الطلاب ولجان المناقشة تلقائياً أثناء جلسات المناقشة عبر كاميرا المنصة.
   * يقوم بإنشاء سجلات تدقيق (Audit Logs) غير قابلة للتعديل.

---

## 4. الميزات الموسعة (الإضافات الجديدة)
للارتقاء بالمنصة إلى تطبيق متكامل على مستوى المؤسسات، تم دمج الميزات التالية في المقترح:

### أ. الاكتشاف المتقدم للانتحال (تحليل شجرة البنية المجردة AST/Code Similarity)
* **الوصف:** في حين يعالج الـ NLP النصوص (الملخصات/التقارير)، تتطلب الأكواد البرمجية تحليلاً خاصاً. يمكن للطلاب تجاوز الـ NLP بسهولة عن طريق إعادة تسمية المتغيرات في الأكواد المنسوخة.
* **التنفيذ:** دمج أداة لمقارنة شجرة البنية المجردة (AST) أو خدمة مثل **MOSS (قياس التشابه البرمجي)** لاكتشاف الانتحال البرمجي بدقة بين التسليمات.

### ب. إدارة المهام ولوحات كانبان (Kanban) المدمجة
* **الوصف:** التقييم المستمر أمر بالغ الأهمية في المشاريع الهندسية.
* **التنفيذ:** لوحة كانبان تشبه Trello (للمهام المطلوبة، قيد التنفيذ، المكتملة) لكل مجموعة مشروع. يمكن للمشرفين تتبع التقدم الأسبوعي، وتعيين المهام، ومراقبة مساهمات الطلاب الفردية، وليس فقط التسليم النهائي.

### ج. دمج أساسيات التحكم في الإصدار (Version Control)
* **الوصف:** تعليم الطلاب معايير الصناعة من خلال دمج التحكم في الإصدارات.
* **التنفيذ:** بدلاً من مجرد رفع الملفات بشكل بسيط، السماح للطلاب برفع إصدارات (v1.0, v1.1) أو دمج الخطافات البرمجية (Webhooks) للمزامنة مع مستودعات GitHub/GitLab الخاصة.

### د. نظام الإشعارات والتنبيهات الآلي
* **الوصف:** تواصل استباقي داخل المنصة.
* **التنفيذ:** إشعارات داخل التطبيق وعبر البريد الإلكتروني لاقتراب المواعيد النهائية، وتعليقات المشرفين الجديدة على الأكواد، والتنبيهات الأمنية الحرجة (مثل محاولات تسجيل الدخول الفاشلة).

### هـ. لوحة تحكم تحليلية لرئيس القسم
* **الوصف:** نظرة عامة شاملة لاتخاذ القرارات الإدارية.
* **التنفيذ:** رسوم بيانية مرئية (عبر مكتبات React مثل Chart.js أو Recharts) تعرض إحصائيات مثل لغات البرمجة الأكثر استخداماً كل عام، ومتوسط درجات التشابه، ومجالات المشاريع الإجمالية.

## 5. الاعتبارات الأمنية والتقنية

كنظام يركز على "الأمن السيبراني" و "الذكاء الاصطناعي"، يجب أن يلتزم التنفيذ بأفضل الممارسات الصارمة لاجتياز التقييمات الأكاديمية والأمنية:

> [!CAUTION]
> **الخصوصية البيومترية وتخزين البيانات**
> * **لا تقم بتخزين الصور الخام** لوجوه الطلاب في قاعدة البيانات.
> * **يجب استخراج وتخزين ترميزات الوجه (Face Encodings)** (متجه مكون من 128 بُعدًا يتم إنشاؤه بواسطة Dlib/Face Recognition). هذا يضمن أنه في حالة اختراق قاعدة البيانات، تكون الصور الفعلية آمنة وتُحفظ الخصوصية.

> [!WARNING]
> **الخطة البديلة لاختبار الحيوية اللحظية (Liveness Detection)**
> * يمكن أن تفشل نماذج الرؤية الحاسوبية بسبب الإضاءة الضعيفة، أو كاميرات الويب منخفضة الجودة، أو ارتداء الطلاب للكمامات/النظارات.
> * **المتطلب:** تنفيذ طريقة بديلة آمنة. في حال فشل المصادقة البيومترية (Face MFA) لـ 3 مرات متتالية، يتم إرسال كلمة مرور لمرة واحدة صالحة زمنياً (TOTP) إلى البريد الإلكتروني الجامعي الرسمي للمستخدم.

> [!IMPORTANT]
> **دعم اللغة العربية في معالجة اللغات الطبيعية (NLP)**
> * عناوين المشاريع والمقترحات والملخصات في جامعة إب ستكون غالباً باللغة العربية.
> * **المتطلب:** مكتبات الـ NLP الإنجليزية القياسية (مثل أدوات التجذير الافتراضية في NLTK) ستكون غير دقيقة للغاية. يجب عليك تنفيذ أدوات NLP مخصصة للغة العربية (مثل `CAMeL Tools`، `Farasa`، أو `ISRI Stemmer` الخاص بـ NLTK) لإجراء عمليات التقطيع وإزالة كلمات التوقف والتحقق من التشابه بدقة.

> [!TIP]
> **تخزين الملفات والحماية من البرمجيات الخبيثة**
> * مع قيام الطلاب برفع ملفات محاكاة وأكواد مختلفة، يتعرض الخادم للخطر.
> * **المتطلب:** تنفيذ تحقق صارم من نوع الملفات (السماح فقط بـ `.py`، `.c`، `.cpp`، `.zip`، `.pdf`، إلخ).
> * **المتطلب:** حظر الصيغ التنفيذية صراحة (`.exe`، `.bat`، `.sh`) لمنع تنفيذ البرامج الضارة عرضياً أو عمداً على خوادم الجامعة.

> [!IMPORTANT]
> **الدفاعات الأمنية القوية لواجهات برمجة التطبيقات (API)**
> * يجب تأمين الواجهة الخلفية (FastAPI) ضد ثغرات الويب الشائعة.
> * **تحديد معدل الطلبات (Rate Limiting):** حماية نقاط تسجيل الدخول من هجمات القوة الغاشمة (Brute-force).
> * **إدارة الجلسات:** استخدام رموز الويب من JSON (JWT) قصيرة الأمد لمصادقة الـ API.
> * **تنظيف المدخلات (Input Sanitization):** منع حقن SQL والبرمجة عبر المواقع (XSS) في جميع حقول إدخال النصوص.

## 6. البنية المعمارية للنظام وتحديث حزمة التقنيات

| الطبقة | التقنيات المستخدمة | الوظيفة في المشروع |
| :--- | :--- | :--- |
| **الواجهة الأمامية (UI/UX)** | React.js / Tailwind CSS | واجهات متجاوبة، دمج الكاميرات، لوحة تحكم تحليلية، لوحات كانبان. |
| **الواجهة الخلفية (Core)** | Python (FastAPI) | تأمين مسارات الـ APIs، منطق صلاحيات الـ RBAC، تشفير كلمات المرور، وإدارة الملفات. |
| **الذكاء الاصطناعي والرؤية** | OpenCV / Dlib / Face_Recognition | التقاط تيار الفيديو، استخراج ميزات البصمة الحيوية، وتطبيق خوارزميات مكافحة التزييف. |
| **معالجة اللغات والانتحال** | Scikit-Learn / Farasa / MOSS | معالجة النصوص العربية، حساب متجهات TF-IDF، والتشابه البرمجي المستند إلى AST. |
| **قواعد البيانات والتخزين** | PostgreSQL / MySQL | التخزين الآمن لبيانات المستخدمين، مصفوفات الأدوار، بيانات المشاريع، وتضمينات الوجوه (Embeddings). |

## 7. الخاتمة والقيمة المضافة
تتجاوز منصة **Secure-FEPRH** كونها مجرد أرشيف بسيط للمشاريع. مع إضافة الاكتشاف القوي للانتحال، وأدوات إدارة المشاريع الرشيقة (Agile)، وممارسات الأمن السيبراني الصارمة، تصبح **مديراً متكاملاً لدورة حياة المشاريع الأكاديمية**.

إنها تتوافق تماماً مع قيود انعدام الميزانية وتوفر في الوقت نفسه منتجاً احترافياً قابلاً للتطوير يعكس قدرات الخريجين في الذكاء الاصطناعي، وتطوير الويب، والأمن السيبراني.
